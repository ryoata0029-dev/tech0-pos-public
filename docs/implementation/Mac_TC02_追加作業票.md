# TC-02：Mac手入力の商品検索・同商品加算・検索遅着の追加試験

2026-10-04。本人の「次に進めます」に基づき、継続中のMac・カメラ以外の残試験を進める。対象は[TC-02](../tests/テストケース.md#tc-02)、[商品受入](../requirements/受入条件_現行.md#r-topic-25)、[設計3.1](../design/画面と業務処理.md#sec-3-1)・[3.2](../design/画面と業務処理.md#sec-3-2)・[4.1](../design/画面と業務処理.md#sec-4-1)。今回アプリは修正しない。

既承認の専用隔離MySQL・架空データ・一時Cloudflare HTTPS方式。新規固定対象 `tech0-pos-mac-tc02-mysql`／専用volume `tech0-pos-mac-tc02-mysql-data`、私有領域 `.mac-tc02-local/`。試験資格情報／Cookieが承認済み中継経路を通る。古いDB・Cookie・期限・証跡を流用・延長・初期化しない。端末の信頼設定を変更せず、TLS検証と通常の認証・API中継を維持する。

1. 通常UIログイン・利用開始・Cookie確認・初回カート作成。商品0001を検索・追加、同商品を再検索・再追加。新行を増やさず同じline_idの数量が1→2となり、追加時単価／税率／固定日時を保持する。成功時だけ検索結果・コードが消えることとDBを照合する。
2. 検索成功後にコード0002へ変更し、旧検索結果・追加ボタンが消えることを確認。未登録PRODUCT_MISSINGの検索404と、登録済み0001の実照会後503を対比する。どちらもカート／明細／版／操作／売上を変えず、不能を不存在と表示しない。再検索により復帰する。
3. 専用backendで通常GET /api/products/0001の実検索が成功し読取トランザクション・接続が終了した後、応答だけを最大600秒停止する。状態や商品結果を直接DBへ注入しない。公開制御APIは作らず、私有releaseファイルで解除する。コード変更と旧応答の扱いを通常UIで試す。
4. 検索中に入力無効で変更できなければその操作条件を不合格として記録し、disabled属性変更・直接状態注入等で回避しない。旧応答上書き条件は成立していないので未確認として分ける。旧200は10秒中継timeout前の解放とtimeout後を区別し、タイミングを証跡で限定する。

今回の503は実検索成功後、更新ロック／読取接続を持たず3秒待って不能を返す。検索応答だけを制御し、登録済み商品を不存在へ偽装しない。GETは読取専用。各検索の前後を別DB接続で確認する。

アプリ版・build ID・端末版、UI・DB・制御到達点・応答分類を保存し独立した欠陥探索レビューを受ける。試験を終えたら今回のトンネル・アプリ・専用DBを停止し、volume・証跡を保持する。iPhone・カメラ／Code128・Chrome全体終了・Azure・commit／push・本番公開／デプロイは含めない。

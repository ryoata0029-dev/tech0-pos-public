## 5. 受入条件

以下は承認済みの受入条件であり、試験結果ではない。試験はすべて未実施。具体的な試験環境・実施手順は後続工程で定める。

<a id="sec-5-1"></a>

### 5.1 操作・保存・技術制約の確認

各項目の節参照は、その節に定義した表示・操作制限・保持／消去・復帰結果を受入条件として確認することを意味する。

<a id="r-topic-21"></a>

#### 利用端末・技術構成

関連：P01〜P04

- MacBook Air・iPhone 15各1台のGoogle Chromeで利用を確認し、構成・設定で指定技術とAPI連携を確認する。
- MacBook Airのモデル・macOS版、iPhone 15のiOS版、両端末のChrome版を実施前に記録する。
- 両端末でカメラを含む対象機能を確認し、一方の結果で他方の合格を代用しない。
- タブレットは確認対象外とする。

<a id="r-topic-22"></a>

#### ログイン・担当者表示

関連：F01〜F03

- 正しい認証情報では通常の空カート・会員未指定のPOS画面へ進み、すぐ商品登録できる。
- 誤認証は拒否。
- 同じIDの直近10分間の5回目の失敗で10分制限し、制限中の正しい資格情報も拒否する。制限期限直前は拒否、期限到達時は自動解除する。追加試行で期限が延びず、別ID・存在しないIDの扱い、ログインと再認証の合算、既存セッション・カート保持も確認する。
- 担当者・指定会員IDの表示と外部ID基盤不使用を確認する。

<a id="r-topic-23"></a>

#### 会員指定・変更

関連：[3.1](機能・非機能要件.md#sec-3-1)

- 会員の登録済み情報を確認する。
- 商品登録前・後、手入力・バーコードで会員指定でき、非会員購入も可能。
- 照会成功・不存在・通信不能・非会員選択の全分岐で[3.1](機能・非機能要件.md#sec-3-1)の表を満たし、リストを保持する。
- AからBへの変更と初回指定の両方で購入制限を確認し、旧会員へ自動復帰せず、旧金額を残す場合は参考表示となる。
- 成功時は保持条件で再計算し、非会員選択ではAの指定・特典も解除する。

<a id="r-topic-24"></a>

#### 会員確認中の操作制限

関連：F04〜F15・F19・T02

- 照会中・不存在・確認不能では、同じ画面・別タブ・直接APIからの商品追加／数量変更／削除／購入を拒否し内容保持。
- 再入力・再照会・非会員選択は可能。
- 確認成功／非会員選択で解除。
- 新しい選択の後に古い照会を完了させても、会員・特典・合計が戻らない。

<a id="r-topic-25"></a>

#### 商品検索・追加

関連：F08〜F12

- 手入力・スキャンで新規商品追加と同一行の数量加算ができる。
- 未登録表示、成功反応、連続読取、リストの表示項目、追加後の入力・表示クリアを確認する。
- 商品はJAN（EAN-13／EAN-8）・Code 128、会員はCode 128で確認し、先頭ゼロ・大小文字を保持する。

<a id="r-topic-26"></a>

#### 連続読取・重複抑止

関連：F09・F10

- 異なる商品を押下なしで続けて追加できる。
- 同じコードを映し続けても数量が増えず案内が表示され、一度枠から外して再提示すると同一行に1個加算する。
- 認識の一瞬の途切れ・API応答待ち・応答不明では重複加算しない。
- 数量上限と会員確認待ち等の制限を維持する。

<a id="r-topic-27"></a>

#### 数量変更・削除

関連：F13〜F15

- 選択行・商品情報を確認し、削除・数量1と99への変更と小計・合計への反映を確認する。
- 0以下・100以上への変更は拒否。
- 99個からの手入力・スキャン追加はエラーとなり、数量99を保持する。

<a id="r-topic-28"></a>

#### 会員値引き

関連：F16〜F18

- 対象商品・期間を変えて割合／定額値引きを確認する。
- 商品登録後の会員指定でも値引きが表示され、設定変更・追加はコード変更なしで反映される。
- 計算は[5.2](受入条件_現行.md#sec-5-2)を満たす。

<a id="r-topic-29"></a>

#### 取引保存・価格履歴

関連：F19〜F22

- 会員・非会員の購入後にDBでF20の記録、購入時単価・値引き内容・売上金額を確認する。
- 商品マスタ単価変更後も確定済み単価・金額は不変。
- 購入の有無にかかわらずマスタ単価変更履歴を確認できる。

<a id="r-topic-30"></a>

#### 合計表示・次取引・税率変更

関連：F23〜F25

- 税抜・税込合計表示と、結果表示を閉じた後のF24全項目のクリア・ログイン維持を確認する。
- 税率をコード変更なしで変更でき、8％・10％混在購入は各商品の税率で[5.2](受入条件_現行.md#sec-5-2)の計算結果となる。

<a id="r-topic-31"></a>

#### 空カート・0円購入

関連：[3.3](機能・非機能要件.md#sec-3-3)

- 商品0件では購入ボタン無効・直接API拒否・DB取引なし。
- 商品あり・値引き後0円の購入は保存できる。

<a id="r-topic-32"></a>

#### 保存失敗・再試行・編集再開

関連：[3.3](機能・非機能要件.md#sec-3-3)

- 成功・確実な未保存・結果不明の各状態で[3.3](機能・非機能要件.md#sec-3-3)の動作を確認する。
- 未保存後の明示的な編集再開ではリスト・会員・既存行の条件を保持し、数量変更・追加・削除・会員指定後に再確定できる。
- 旧要求の遅延到着で古い内容を保存しない。
- 保存後の応答断では内容を保持し、保存中・不明時は編集・次取引不可。
- 再試行・連打でも取引は1件で、保存済みなら同じ結果を取得できる。

<a id="r-topic-33"></a>

#### 再読込・ブラウザ終了後の復帰

関連：[3.4](機能・非機能要件.md#sec-3-4)

- 同一端末・ブラウザの通常モードで、状態表の全5状態を再読込とブラウザ終了・再起動の両方で確認する。
- マスタ変更後も既存行の条件は不変。
- 応答断の商品追加は反映を照合して二重加算せず、購入の自動送信・二重保存もない。
- 未送信入力・選択行・カメラ映像は復元しない。
- 認証失効時は同じ担当者の再認証を必要とし、別担当者は拒否する。

<a id="r-topic-34"></a>

#### 復帰期限・初回利用の識別

関連：[3.4](機能・非機能要件.md#sec-3-4)

- 最後の反映済み業務操作から24時間経過前の復帰、経過後・Cookie消失時の停止を確認する。
- 表示・照会では期限が延びず、停止中はレジ操作で復帰・新規購入できず、自動取消・削除もない。
- 初回識別表の全4条件を確認し、取引終了後も開始済み記録が残る。
- 開始済みでCookieなし／無効なら、取引の有無にかかわらず画面・APIから新規購入不可。
- 手動確認・再開手順は設計後に確認する。

<a id="r-topic-35"></a>

#### 復帰期限とCookieの管理

関連：[3.4](機能・非機能要件.md#sec-3-4)

- 起算更新対象のDB確定で24時間を起算し、更新対象外の操作では延長しない。
- 応答断でもDB確定済みならサーバーの時刻を採用。
- ブラウザ時計変更で判定が変わらず、業務更新の応答で同じ復帰Cookieの保持期限が30日へ更新される。
- Cookieが残っていても24時間経過時は停止する。

<a id="r-topic-36"></a>

#### 手動確認後の復帰

関連：[3.4](機能・非機能要件.md#sec-3-4)

- 本人の手動確認・許可後、許可日時から24時間経過前は同じ対象へ復帰でき、経過時は停止する。
- 許可日時を別記録し、元の業務日時・購入日時・売上は不変。
- 許可後の業務更新は新しい起算となり、照会・再認証だけでは延長しない。
- 認証・Cookie・購入状態の制限を維持する。

<a id="r-topic-37"></a>

#### 取引・操作記録の保持

関連：F19〜F22・T02・[3.4](機能・非機能要件.md#sec-3-4)

- 復帰期限切れ・Cookie消失後も途中カート・操作・売上・履歴が残り、自動削除の実装・定期処理がないことを構成とデータで確認する。
- 演習終了後の削除は本確認に含めず別途対象確認する。

<a id="r-topic-38"></a>

#### 複数タブからの操作

関連：[3.5](機能・非機能要件.md#sec-3-5)

- 2タブで警告表示を確認する。
- 一方の更新後、他方の古い更新は拒否され、先の変更を上書きせず再取得を求める。
- 両タブの購入確定でも取引は1件。
- 警告を無視してもサーバーの状態制限・二重保存防止が有効である。

<a id="r-topic-39"></a>

#### 会員属性の確認（F04／3.1）

- 6属性が揃った登録を受理し、各属性の欠落・NULL、文字列の空文字、年齢の負数・小数を投入前に拒否する。
- 年齢0は受理する。
- 保存先型の容量超過を丸め・切捨てで受理せず、性別を独自の選択肢へ限定しない。
- 初期登録・マスタ更新の両方で確認する。
- POSへ会員属性の編集機能は追加しない。

<a id="sec-5-2"></a>

### 5.2 金額計算の確認例

商品追加後に単価・税率・値引き条件を変更、または値引き期間が終了しても、同じ商品の追加・数量変更・後からの会員指定・購入確定・保存再試行には最初の追加時点の条件が使われることを確認する。商品行を削除して再追加した場合は、その再追加時点の条件が使われることを確認する。

| 条件 | 期待結果 |
|---|---|
| 税抜103円×3個、会員値引き10％、税率10％ | 1個の値引き10円、値引き後小計279円、税27円、税込306円。 |
| 上記に、値引きなし・税率8％の107円の商品を異なる2商品各1個追加 | 8％対象小計214円・税17円、10％対象小計279円・税27円。税抜合計493円、税込合計537円。 |
| 税抜103円に10％引きと20円引きが同時に該当 | 値引き額10円と20円を比較し、20円引きだけを適用。値引き後単価83円。 |
| 税抜103円に120円引きを適用 | 値引き後単価0円。小計・税額とも0円。 |

<a id="sec-5-3"></a>

### 5.3 非機能の確認

<a id="r-topic-40"></a>

#### 応答時間

関連：N01・T03

- Azure上のアプリを、通常利用する安定した回線で測定する。
- 同じ端末・ネットワーク・データ条件で、通常時は商品検索・会員照会・購入確定を各10回、30分間アクセスしなかった後は各操作1回測定する。
- 放置後の確認では、各対象操作の測定前にそれぞれ30分間アプリへアクセスしない。
- 平均ではなく、測定した各回が2秒以内であることを確認する。
- 回線障害時は2秒保証の対象に含めない。

T03の測定回数は演習としての最低限の確認であり、営業時間全体の安定性を証明するものではない。

<a id="r-topic-41"></a>

#### 実行環境・DB接続

関連：N02

- 構成・起動記録から毎回ゼロから起動する構成でないことを確認し、DB接続維持の採否を設計で説明する。

<a id="r-topic-42"></a>

#### 認証情報の保護・未認証アクセス

関連：T04（F01・F02）

- 保存データ・ログに平文パスワードがなく、パスワード保存用のハッシュ方式が使われることを確認する。
- 未ログインではPOS画面を利用できず、APIへの直接アクセスによる商品・会員情報取得・取引保存も拒否される。
- 担当者ID誤り・パスワード誤りのいずれでも[4.2](機能・非機能要件.md#sec-4-2)の共通エラーが表示される。

<a id="r-topic-43"></a>

#### ログイン期限・認証応答不明

関連：[4.2](機能・非機能要件.md#sec-4-2)・F01・F02・T04・T02

- 認証成功から8時間経過前は有効、経過時は失効。
- 操作・無操作で期限が動かず、同じ担当者の再認証成功で新たに8時間となる。
- 応答断後の照会で有効／未認証／照会不能の3分岐が[4.2](機能・非機能要件.md#sec-4-2)どおりとなり、内容・購入状態を保持する。
- 通常復帰24時間を認証更新で延長しない。

<a id="r-topic-44"></a>

#### 認証Cookieの保護・切替

関連：[4.2](機能・非機能要件.md#sec-4-2)・F01・F02・T04・T02

- CookieのHTTPS限定・JavaScript読取禁止、他サイトからの更新拒否を確認。
- 再認証後の旧認証は無効。
- 認証応答を逆順に到着させても旧認証を復活させず、内容保持・照会／再認証となる。
- 照会不能時は操作を再開せず、購入も自動送信しない。

<a id="r-topic-45"></a>

#### 取引中の再認証

関連：F01・F02・T04・T02

- 編集中・会員確認待ち・保存中・結果不明で期限切れを発生させ、[4.2](機能・非機能要件.md#sec-4-2)の保持・操作停止・復帰を確認する。
- 同じ担当者だけが元状態へ戻れる。
- 保存中・結果不明からの復帰では結果確認前の編集・次取引は禁止し、再認証による保存自動送信も行わない。
- 保存済みは結果表示、確実な未保存は再試行／修正を選べる。
- 誤認証・別担当者では内容保持のまま再開不可。
- 通常ログインの空カート・会員未指定とは区別する。

<a id="r-topic-46"></a>

#### 運用・データ保護の確認（4.3）

- バックアップと診断ログの保持設定が各7日、本人以外のログ閲覧が制限され、ログに秘密値・会員属性・要求本文が含まれないことを確認する。
- 異常時の停止・本人確認と既定の入力エラー処理を照合する。
- 診断ログの期限が途中記録・売上・履歴の削除に連動しないこと、専用監視画面・外部通知連携を追加していないことも確認する。
- 復元可能性は設定確認とは分け、別途許可された復元・照合で検証する。

<a id="sec-5-4"></a>

### 5.4 境界値の確認

[3.6](機能・非機能要件.md#sec-3-6)に対応し、以下を確認する。

| 対象 | 確認内容 |
|---|---|
| コード・ID | 1／32文字は受理、0／33文字・空白・全角は拒否。先頭ゼロと大小文字を保持し、手入力・読取・APIで同じ判定 |
| 金額・率 | 0・上限を受理。負数・上限超過・整数でない円額・0.01％刻みでない率を拒否。集計超過でも元カートを保持し売上を部分保存しない |
| 時刻・期間 | 開始ちょうどは対象、終了ちょうどは対象外。日本時間の期間設定とUTC保存が一致。追加済み行は終了後も条件を保持。保存済み結果の再送で購入日時は不変 |
| 同額候補 | 候補の取得順に関係なく、条件ID昇順の同じ1件を適用・記録 |

# Mac Chrome：通信障害・復帰の追加試験

2026-10-03。本人が「次は？」への説明（環境再準備→購入/next応答断→状態別完全終了再起動）に対して「進めてください」と指示した範囲で実施する。カメラは前回の「まずカメラ以外」を維持する。

## 対象と境界

新規隔離MySQL `tech0-pos-mac-recovery-mysql`、専用volume `tech0-pos-mac-recovery-mysql-data`、DB `pos_validation`、秘密値はGit除外 `.mac-recovery-local/`、証跡は `docs/implementation/evidence/mac-recovery/`。前回の `tech0-pos-mac-flow-mysql` と期限切れカート/売上/volume/証跡は停止保持し、延長・復旧・初期化しない。これは未完了対象の新取引による回避ではなく、[実施条件](../tests/実施条件.md)に従う別の試験領域である。

前回許可された方式と同じ固定MySQL、架空担当者/会員/3商品、localhost TLS、Cloudflare一時HTTPS、画面とAPI中継だけの公開。試験専用資格情報・Cookie・架空業務データがCloudflareを経由する。FastAPIとDBはloopbackのみ。証明書信頼設定・既存環境・Azure・本番は変更しない。

## 条件と方式

F20〜25、業務手順4〜6、設計3.5/7/8、[TC-16〜21・24](../tests/テストケース.md)のMacブラウザ条件を対象とする。実MySQLのCOMMIT ACK喪失は[M4](M4_実DB障害競合検証.md)の別証拠であり、ブラウザ応答喪失と混同しない。

1. ブラウザから新規ログイン・初回利用を開始し、商品あり編集状態を作る。APIクライアントのCookieを移植しない。
2. 専用バックエンドだけに試験用ラッパーを適用し、実受付COMMIT後・会員照会前の503と、実購入受付COMMIT後・売上TX前の停止を発生させる。DB状態の直接書換え・偽レスポンスの状態注入はしない。制御は私有ローカルファイルだけで行い、公開障害APIを作らない。
3. 専用HTTPSハーネスで実アプリの購入/next応答を読み終えてからブラウザ接続を切る。秘密値や応答本文を証跡へ出さず、操作ID・カートID・状態等だけを残す。別接続のDB読取で指定位置の確定を検証する。
4. 編集中・会員待ち・SAVING・結果不明・UNSAVED・SAVED・next移行済みを、再読込とChrome完全終了再起動で別記録する。SAVINGは正規のresolveによるUNSAVED等への結果確定を判定し、自動再購入を許さない。状態を作り直した場合は別実行としてIDを記録する。
5. Chrome完全終了では試験外タブへの影響を直前に確認し、必要なら本人の作業保存を待つ。ネイティブChrome終了、プロセス終了の読取確認、同じ通常プロフィール/一時URLで再開を別々に記録する。ウインドウ閉鎖・タブ再読込で代用しない。

各状態の開始/復帰画面とDBを照合し、未送信入力・選択行・カメラを復元せず、確定購入の不変性と購入件数を確認する。多重再送・通知欠落・補助記録破損・状態別再認証の全条件まで、この実施だけで合格へ拡張しない。制御の不成立は未実施/不能として記録する。

## 終了・戻し

試験用の停止/遮断を解除し、必要な結果照合を先に行う。今回のトンネル・両アプリ・MySQLだけを停止し、ポート閉鎖・volume保持・秘密値非混入を確認する。確定売上・証跡を削除しない。戻しは検証器と専用profileの差分だけに限定する。commit/push/デプロイは行わない。

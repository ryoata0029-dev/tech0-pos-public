# TC02-P2-01：商品検索中にコードを変更できない

後続（2026-10-04）：残作業①②③の並行指示により[コード修正・自動回帰](Mac_TC02_修正再検証.md)を実施。165件とbuildが成功。Mac実DBの修正後確認はまだ未実施であり、実機解消・TC全体合格とはしない。以下は発見時の記録。

2026-10-04。P2、未修正。Mac通常Chrome・手入力で再現。[追加結果](Mac_TC02_追加結果.md)、[作業票](Mac_TC02_追加作業票.md)。

対象：[TC-02](../tests/テストケース.md#tc-02)、[商品受入F08〜F12](../requirements/受入条件_現行.md#r-topic-25)、[設計3.1](../design/画面と業務処理.md#sec-3-1)。TC-02は「検索中にコード変更、旧応答を遅着させる」を指定し、設計はコード変更による旧結果・追加可否の消去と旧応答の非表示を規定する。

通常UIで商品0001を検索し、専用試験backendが実照会を完了して読取トランザクション／接続を閉じた後、200応答だけを保留する。この間の商品コード欄はdisabledで、0002へ変更できない。入力可能性falseを取得し、disabled除去や直接状態変更は行っていない。[実照会到達](evidence/mac-tc02/gate-lookup-held.json)、[UI](evidence/mac-tc02/ui-lookup-held.txt)、[入力可否](evidence/mac-tc02/ui-held-input.json)。

原因は `frontend/app/register-cart.tsx` の検索開始でbusy=trueとなり、editing／canEditがfalse、商品コードinputがdisabledとなる経路。入力変更時の結果クリアと `inputCode.current === searched` による応答ガードは存在するが、通常操作で条件を成立させられない。旧応答が新コードへ上書きした不具合と断定しない。

期待する修正範囲は読取専用の商品検索待ち中のコード入力のみ。更新要求の多重送信、商品追加・購入、会員確認待ち、応答不明、認証失効・停止条件は維持する。コード変更後に旧成功と旧エラーが戻る条件、および新コードの正常検索・追加を自動回帰と新規隔離Mac環境で検証する。要件変更によって試験を除外せず、現行設計に合わせて修正する。

今回アプリは変更していない。専用環境は停止・volume／証跡保持。iPhoneでの修正後確認と本人受入は別途必要。

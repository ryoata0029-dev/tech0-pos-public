## 対象限定の1回分のSQL

独立レビューで、pos_masterには元のマスタ保守DMLが残り、復旧専用の最小権限とは言えないこと、空カート全属性と停止解除SQLの具体化不足を指摘された。修正として、専用pos_recovery（REQUIRE SSL）へ9表のSELECTとREGISTERの2列、AUTH_SESSIONのrevoked_at、BROWSER_CONTEXTの2列、CARTのversionだけを作業時付与する。pos_masterへ追加した復旧権限は取り除き、元の保守権限へ戻す。アプリには復旧資格情報を渡さない。

停止中にREGISTER→BROWSER_CONTEXT→CART→AUTH_SESSIONをロックし、上記ID・元版・元担当者・元状態・元照合値、操作／売上不存在を確認してから実行する。`%s`は既存DBクライアントのパラメータとしてプロセス内から渡し、秘密値をSQLファイルへ展開しない。以下の文だけでは実行結果を意味しない。

       active_session_hash

       manual_released_at, invalidated_at
FROM BROWSER_CONTEXT

## 照合後の対象限定停止解除

アプリを保守停止で起動し、新Cookie・同じ担当者の再認証後、ブラウザのGETで元のカート・version=2と保守停止を確認。業務更新POSTがMAINTENANCE_HOLDで拒否されることも確認する。次のTXはREGISTER→context→cartを再ロックし、新照合値・同じ担当者の有効セッション・空カート全属性・件数・manual_released_atの期限判定を照合してから実行する。

```sql
START TRANSACTION;
SELECT start_state, maintenance_hold, active_context_id, current_cart_id,
       active_session_hash FROM REGISTER WHERE register_id=1 FOR UPDATE;
SELECT register_id, token_hash, starting_staff_id, confirmed_at, last_business_at, manual_released_at,
       invalidated_at FROM BROWSER_CONTEXT
WHERE context_id='e5f8b91d-f145-421b-bf38-89fcaea9552c' FOR UPDATE;
SELECT register_id, context_id, staff_id, state, version, member_state,
       member_id, pending_member_id, active_member_operation_id,
       active_purchase_operation_id, purchase_prepared_version,
       subtotal, total, tax_breakdown, created_at, updated_at, result_closed_at
FROM CART WHERE cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f' FOR UPDATE;
SELECT line_id FROM CART_LINE
WHERE cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f' FOR SHARE;
SELECT operation_id FROM CART_OPERATION
WHERE cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f' FOR SHARE;
SELECT cart_id FROM PURCHASE
WHERE cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f' FOR SHARE;
SELECT cart_id, line_no FROM PURCHASE_LINE
WHERE cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f' FOR SHARE;
SELECT cart_id, tax_rate_snapshot FROM PURCHASE_TAX
WHERE cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f' FOR SHARE;
SELECT staff_id, created_at, expires_at, revoked_at FROM AUTH_SESSION
WHERE token_hash=%s AND register_id=1 FOR UPDATE;
-- 新照合値一致、STAFF_A、version=2、失効なし、session期限内、
-- UTC現在時刻がGREATEST(last_business_at,manual_released_at)+24時間より前。
-- 前TXの業務日時・状態・金額・子表0行も維持していることを必須確認。
UPDATE REGISTER SET maintenance_hold=FALSE
WHERE register_id=1 AND maintenance_hold=TRUE AND start_state='READY'
  AND active_context_id='e5f8b91d-f145-421b-bf38-89fcaea9552c'
  AND current_cart_id='213f366b-49e3-4b6c-9acb-08d051ceac3f'
  AND active_session_hash=%s;
-- 1件と変更後hold=FALSEを確認してCOMMIT。不一致はROLLBACK。
```

COMMIT後にpos_recoveryの9表SELECT・必要列UPDATEを全て撤去し、SHOW GRANTSでUSAGEだけを確認。アカウントは削除せず保持し、復旧資格情報をアプリへ追加しない。

Cookieの名前・Domain空欄・Path=/・Secure/HttpOnly・SameSite=Lax・非Session・2026/10/31 14:00:00期限をInspectorで準備し、本人による値の入力・保存を確認した。復帰Cookieは認証情報なので、操作ツールの規約に従い**新しい値の入力・保存だけ本人操作**とした。私有`recovery-entry.txt`の1行をコピーし、Safariの追加フォームの「値」へ貼付、フォーム外の一覧見出し「名前」で保存するよう引き渡した。値やスクリーンショットを返信へ添付しないよう案内した。値を伏せた属性照合と上記TXを終え、同じ担当者の再認証→元context/cart・version=2の読取照合を保守停止中に実施。業務更新拒否を確認した後に対象1件のmaintenance_holdを解除し、作業権限を外した。

独立Cookie試験の旧トンネルは停止後のHTTP 530を確認。この作業時には新URL・iPhone用POSとDBを保守停止で起動し、私有ファイルを本人へ案内した。続く追加試験の終了後、POS・DB・トンネルを停止し、Inspector無効化・クリップボード上書きを本人が報告した。終了証跡は[同一URL追加試験](M2_手動復旧_同一URL追加試験.md)を参照。

COMMIT前はROLLBACK。COMMIT応答不明なら新接続で照合し、無条件再実行しない。COMMIT後に旧照合値・失効認証を復活させず、不一致なら停止継続する。元の取得不能な旧Cookieの実HTTP拒否は未確認。元の旧Cookieを取得できないままなら、その個別試験を合格にしない。追加試験は別記録で判定する。
